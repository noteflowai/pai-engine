# ADR 0003 · 本体为核心、通道为插件的分层架构

状态：已采用（2026-10-11）。接 ADR 0002。逐步迁移，每一步单独 PR，行为不变。

## 背景

ADR 0002 引入了本体，但它目前**在核心旁边**：只有 `server.ts`（注册路由）和 `agent-api.ts`（过滤读取）用它；写入、权限和审计不经过它，本体与代码靠契约测试保持一致，而不是靠结构。2026-10-11 实测：

- 记录种类以字符串字面量散落各处：`"cad-review"` 51 处、`"scene-review"` 44 处、`"aero-review"` 28 处，拼错只在运行时暴露。
- `server.ts` 535 行、65 个路由、51 个 import，路由、鉴权、边界检查和部分业务混在一起。
- 通道互相依赖：`cad` ↔ `scenes` 循环，`aero` 依赖 `scenes`，`ai.ts` 引入 20 个模块，`lifecycle` 认识每个通道。
- 原生运行的公共逻辑（按 requestId 认领、回执、源摘要复核、运行中 → 完成/失败、独立对照、证据文件哈希）每个通道各写一遍。
- 证据种类映射分在三处：`release.ts` 的 `KIND_STORE`、本体的 `RUN_TARGET`、各通道内的 `kind`。

## 决策

目标：**本体是唯一的领域模型并驱动运行时；通道是登记进来的插件；公共能力只实现一次。**

| 层 | 职责 | 依赖方向 |
|---|---|---|
| 本体（`src/ontology/`） | 对象类型（带种类、schema）、链接、动作；类型化的种类句柄 | 不依赖任何通道 |
| 内核（`src/kernel/`） | 存储、动作运行时（解析 → 授权 → 请求认领 → 审计）、原生运行内核 `NativeRun`（隔离命令、回执、源摘要、状态机、证据哈希、不重放）、投影（对象读取、Agent / 租户可见集） | 只依赖本体 |
| 通道插件（CAD、场景、机器人、气动、工厂、制品） | 声明自己的对象类型、动作、检查和引擎；只写"构造输入 → 调用求解器 → 解读检查" | 依赖内核与本体，通道之间不互相依赖 |
| 产品（生命周期、发布、AI、租户、界面） | 通过注册表读通道，不 import 具体通道 | 依赖内核与注册表 |

## 迁移步骤（每步一个 PR，行为不变）

1. **类型化种类**：`RecordKind` 联合类型由本体定义，`Store` 的每个方法只接受它；拼错的种类成为编译错误。契约测试保证本体种类与存储种类一致。
2. **原生运行内核** `nativeRun`（`src/kernel/native-run.ts`）：✓ 气动、CAD、场景 / 产线 / 机器人单元已迁移（PR #34、#35）。工厂孪生评估是同步的只读核对，没有运行中状态，不套用这个生命周期。
3. **动作运行时**（`src/kernel/actions.ts`）：✓ 全部 46 个写路由都由 `action(id, handler)` 从本体动作类型注册，按动作声明的提交者授权（维护者 / Agent scope / 租户）；契约测试禁止手写写路由，并核对每个 Agent 写路由的 scope 都列在对应动作的提交者里。参数仍由拥有它的领域函数用同一个 schema 校验，保留具体错误（如 422 WORKFLOW_SCHEMA）。审计记录留到步骤 5。
4. **通道插件登记**：✓ 运行时导入图没有环（原有 15 个，其中 11 个来自 `config` ↔ 租户，已拆出叶子模块 `tenant-config.ts`）；通道之间不再互相导入（阶段事件移到 `kernel/native-events.ts`，零件族移到共享契约 `part-family.ts`）；证据种类映射只剩 `ontology/evidence.ts` 一张表；自主授权从通道注册表 `src/lanes.ts` 分发。架构契约测试（`tests/architecture.test.ts`）锁住：无运行时环、通道互不导入、内核与共享契约不导入通道、已迁移的产品模块只经注册表访问通道。尚未迁移：`ai.ts` 直接使用各通道的请求 schema，`lifecycle.ts` 使用场景的纯函数 `sceneKey`。
5. **投影与审计**：✓ `/api/state`（以及 Agent 的 `/api/agent/state`）的记录列表由本体的工作区投影 `WORKSPACE_FIELDS` 生成，Agent 的对象读取范围就是这张表，二者不会漂移；✓ 动作运行时为每次写入尝试（完成、已受理、拒绝、无效、失败）追加一条 `AuditEvent`：动作、调用方（维护者 / Agent scope / 租户）、执行者、路径中的编号、状态码、耗时，**不记录请求体**；只有维护者可读（`GET /api/v1/audit`），Agent 与租户都读不到。

**迁移完成（2026-10-11）**：五步全部合并并部署。尚留的改进：`ai.ts` 直接使用各通道请求 schema，可改为从通道注册表读取。

每一步都由现有单元测试、浏览器测试和原生 e2e 证明行为不变，并新增结构性契约测试（依赖方向、无循环、无种类字面量）锁住新结构。

## 后果

- 新增对象类型或动作从本体开始，编译器和契约测试指出所有需要实现的地方。
- 通道可独立开发与测试；公共规则（隔离、未知结果需核对、不重放）只在内核里维护一份。
- 迁移期间新旧方式并存，以步骤 5 完成作为结束标志。
